# NAS Hermes 职责清单（L1 数据服务）

> 2026-09-28 架构调整：**采集全部移至办公室 Hermes 单机**（含星耀 3 指标），NAS 不再跑采集任务卡。
> NAS 职责 = **数据库正本 + 分析结果服务**。本仓库零凭据；凭据见 wiki `量化开发/运维/L1凭据.md`。

## 数据流

```
办公室 Hermes (每天21:30 cron)
  └─ l1_update.py --all --state-from pg  →  18 指标增量 UPSERT
                                              ↓
                                      NAS PG (quant, 正本)
                                              ↓
                              NAS 分析服务 (阶段3: 网站 + API)
                                              ↓
                              用户看板 / 办公室 Hermes 拉结果
```

## NAS 职责

### 1. 数据库正本（现状，无需动作）
- PG `quant` 库 `l1_observation` 等三表，18 指标，47085+ 行
- 读写均从办公室来；**NAS 侧只读勿改**

### 2. 定时健康检查（可选，建议）
- **触发**：每天 `09:00` 或 `10:00`
- **检查**：`l1_observation` 各指标最新日期 vs 预期（日频=最近交易日、月频=按滞后天数）
- **动作**：缺数/过期 → 推送用户（`shrzgm` 停更需人工补数是已知项）
- **命令**（只读，不落盘）：
  ```bash
  python l1_update.py --all --state-from pg --dry-run
  ```
  dry-run 不写库，输出缺数判断供告警参考

### 3. 分析结果服务（阶段 3，待办公室出规格后建）
- 网站：用户看 L1 指标仪表盘（最新值/更新时间/缺数告警）
- API：`/api/v1/l1/*` JSON，供办公室 Hermes / L2 / L3 拉取
- 部署：NAS Docker 容器 + Tailscale 暴露（100.76.208.125）
- 规格：由办公室 Hermes 出 API 契约，webdev agent 开发，default agent 运维

## 运行注意事项

1. **采集不再在 NAS 跑**（星耀 SDK 依赖 tgw，tgw 底层库含 AVX 指令，NAS 的 Celeron J4025 无 AVX → SIGILL，硬件级无解）——所以星耀 3 指标（国债/两融/申万市值）由办公室采集
2. **网络**：akshare/FRED 直连；勿配代理环境变量
3. **凭据**：NAS 如需连 PG，凭据从 wiki `量化开发/运维/L1凭据.md` 读取（NAS 同步可见）
4. **只增量**：脚本只 append 新行，绝不重写历史；补数类写库必须走确认卡
5. **故障**：采集失败告警由办公室 cron 处理；NAS 侧只负责数据库健康与服务可用性

## 故障速查（NAS 侧）

| 症状 | 处理 |
|---|---|
| PG 数据过期（办公室 cron 失败） | 用户会收到办公室告警；NAS 无需动作，或提示用户联系办公室 |
| 数据库磁盘/服务异常 | 推送用户；办公室负责数据重建 |
| 分析服务不可用（阶段3） | 重启 Docker 容器；重启失败推送用户 |
