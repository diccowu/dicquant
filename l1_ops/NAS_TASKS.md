## 任务卡 1：L1 日常更新（阶段 1）

- **触发**：每天 `21:30`（日频数据当日发布完毕；FRED 美债滞后一天可接受）
- **命令**：
  ```bash
  cd ~/dicquant/l1_ops && .venv/bin/python l1_update.py --all --state-from pg --pit-init ~/dicquant/l1_ops/pit_init.py
  ```
- **输出**：更新摘要（新增 N 行 / 无新数据 / 失败明细）
- **推送**：正常 → 静默或一行摘要；**失败/异常 → 推送用户**（家里 Hermes 现有渠道）
- **幂等**：脚本幂等，重复跑无副作用，可放心补跑

## 任务卡 2：数据健康检查（阶段 1）

- **触发**：每天 `09:00`
- **检查**：每个指标 PG 最新日期 vs 预期（日频=最近交易日、月频=按滞后天数）
- **动作**：缺数/过期 → 推送告警（如 `shrzgm` 停更需人工补数）
- **命令**：

  （dry-run 不落盘，输出缺数判断供告警参考）

## 任务卡 3：shrzgm 半自动补数（阶段 2，待办公室出补数脚本后配置）

- **触发**：每月 `16~20 日`（央行次月中旬发布）
- **流程**：检查 akshare 缺最新月 → 抓央行《金融统计数据报告》→ 累计差分出单月增量 → 生成**补数确认卡**推用户（数值+来源URL+差分过程+口径判断）→ 用户确认 → 写 CSV+PG+台账
- **铁律**：未经用户确认**禁止**写库（定稿数据口径终裁权在人）

## 运行注意事项

1. **星耀单点登录**：办公室与家里**不能同时跑**。默认家里跑；办公室仅在特殊验证时跑，跑前确认家里未在执行
2. **网络**：akshare 直连；FRED 直连（办公室无代理实测可达，NAS 更没问题）；**勿配代理环境变量**（会影响 akshare 直连）
3. **环境**：Python venv，依赖 `akshare pandas psycopg2 amazingdatasdk`
4. **凭据**：脚本已内置默认（星耀账号 / NAS PG），可用环境变量 `AD_USERNAME`/`AD_PASSWORD`/`L1_PG_DSN` 覆盖；**勿把新凭据写进代码**
5. **只增量**：脚本只 append 新行，绝不重写历史；补数类写库必须走确认卡

## 故障速查

| 症状 | 处理 |
|---|---|
| PG 连不上 | keepalive 已内置；检查 Tailscale（100.76.208.125）连通 |
| akshare 报错 | 东财改版/停更 → 记入告警，**等办公室技术支持**（勿自行改采集逻辑） |
| FRED 超时 | 偶发网络, 重试; 确认未配代理环境变量 |
| 星耀登录失败 | 大概率办公室同时在跑（单点登录）→ 错开时间 |
| 数值异常（量级跳变） | 推送用户 + 等办公室技术支持，**勿自动回填** |
